# AI Stock Simulator 개발 계획 초안

시장 상태 관리부터 매매·자산 계산, 반복 시뮬레이션, 화면·차트, AI 연동, 배당 순서로 개발한다. 먼저 고정 뉴스로 투자 흐름을 완성하고, 같은 이벤트 형식으로 AI 뉴스를 연결한다.

이 계획은 팀 리뷰를 위한 제안이다. 개발 순서와 완료 기준을 먼저 맞추고, 담당자와 세부 게임 규칙은 아래 논의 항목을 기준으로 정한다.

관련 문서: [팀 제안서](PROPOSAL.md), [실행 방법](README.md)

관련 작업: [기본 구조 PR #51](https://github.com/hist0613/HUFS-LAI-AISE-2026-2/pull/51), [개발 계획 이슈 #55](https://github.com/hist0613/HUFS-LAI-AISE-2026-2/issues/55)

## 현재 구현 범위

PR #51의 `9c159cd` 커밋을 기준으로 한다.

| 파일 | 구현된 내용 |
| --- | --- |
| `events/sample.mjs` | 뉴스 제목, 대상 종목 ID, 변동률을 가진 고정 이벤트 한 건 |
| `market/engine.mjs` | 현금 100만 원·종목 2개로 초기화, 대상 종목 가격 계산 |
| `demo.mjs` | 초기 상태와 뉴스, 가격 변동 전후를 콘솔에 출력 |

`applyEvent()`는 새 종목 배열을 반환하며, 현재 데모는 이를 출력만 하고 `game.stocks`를 갱신하지 않는다. 매매, 보유 수량, 시간 진행, 화면과 AI 호출은 후속 개발 범위다.

## 개발 순서와 완료 기준

각 단계는 리뷰 가능한 크기의 PR로 나누고, 계산 로직을 추가하는 PR에는 해당 동작을 확인하는 테스트를 함께 포함한다.

| 순서 | 구현할 기능 | 확장할 부분 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 게임 상태 갱신과 이벤트 검증 | `market/engine.mjs`와 공통 이벤트 검증 | 이벤트 결과가 다음 계산의 입력 상태에 반영된다. 존재하지 않는 종목과 잘못된 변동률은 상태를 바꾸지 않는다. |
| 2 | 매수·매도 | 보유 수량·거래 내역, `market/trading.mjs` 등 거래 모듈 | 현재 가격으로 거래하고 현금과 보유 수량을 함께 갱신한다. 잔액·보유량 부족과 잘못된 수량을 거부한다. |
| 3 | 자산 조회와 다시 시작 | 평가액·총자산·전체 수익률 계산, 초기화 | 시세 변동이 평가액에 반영된다. 재시작하면 현금 100만 원·초기 시세·빈 보유 및 기록 상태로 돌아간다. |
| 4 | 턴 진행과 가격 이력 | 한 턴 진행 함수, 턴별 뉴스·가격 기록 | 다음 턴마다 이벤트를 한 번 적용하고 가격 이력을 순서대로 기록한다. |
| 5 | 화면과 차트 | 종목 목록·주문·자산·뉴스·가격 이력 화면 | 화면에서 거래와 턴 진행이 가능하다. 모든 화면이 같은 게임 상태를 사용하고 차트가 이력과 일치한다. |
| 6 | AI 뉴스 생성 | 이벤트 생성 모듈, AI 응답 검증 | 기존 이벤트 형식으로 생성한 응답을 검증한 뒤 엔진에 전달한다. 생성 실패 시 상태를 유지하고 재시도나 예제 이벤트를 선택할 수 있다. |
| 7 | 배당과 시장 확장 | 배당 규칙·지급 기록, 종목 확대·자동 진행 | 보유량에 따라 배당을 중복 없이 지급한다. 10~20개 종목과 자동 진행에서도 거래·가격·자산 계산이 일치한다. |

1~4단계에서 콘솔로 투자 흐름을 확인하고, 5단계에서 화면으로 연결한다. 화면과 AI 이벤트 생성은 공통 데이터 형식을 맞춘 뒤 예제 데이터로 병행 개발할 수 있다. 자동 진행은 수동 턴 진행을 검증한 뒤 추가한다.

## 다음 구현 PR의 범위

첫 구현 PR은 1단계인 게임 상태 갱신과 이벤트 검증에 집중한다.

- 기존 `applyEvent(stocks, event)`는 가격 계산 역할을 유지한다.
- 계산 결과를 반영한 새 게임 상태를 반환하는 함수를 추가한다. 함수 이름과 입출력 형식은 구현 이슈에서 맞춘다.
- 이벤트의 필수 필드, 존재하는 종목 ID, 유한한 숫자인 변동률을 검증한다. 허용 변동률 범위와 오류 반환 방식도 구현 전에 정한다.
- 데모를 여러 뉴스의 순차 적용으로 확장한다.
- 다음 동작을 테스트로 확인한다.
  - 삼송전자에 2% 상승을 두 번 적용하면 50,000원 → 51,000원 → 52,020원이 된다.
  - 대상이 아닌 종목과 현금은 그대로 유지된다.
  - 호출 전 원본 상태는 직접 수정하지 않는다.
  - 잘못된 이벤트는 부분 반영 없이 거부된다.
  - 기존 가격 계산의 원 단위 반올림과 최저가 1원 동작을 유지한다.

매매, 화면과 실제 AI API 연결은 각각 후속 PR로 진행한다.

## 함께 개발하기 위한 연결 규칙

기존 이벤트 형식을 공통 입력으로 사용한다.

```js
{
  headline: "삼송전자, 차세대 반도체 시제품 공개",
  stockId: "samsong",
  changePercent: 2
}
```

`changePercent`는 퍼센트 단위로, `2`는 2% 상승이다. 뉴스 제목과 변동률 생성은 이벤트 영역에서 담당하고, 가격·현금·보유 수량 계산은 시장 영역에서 담당한다.

게임 상태는 현재의 `cash`, `stocks`를 출발점으로 삼는다. `holdings`, `trades`, `turn`, `priceHistory` 등은 필요한 단계에서 추가할 필드의 예시이며, 각 형식은 해당 구현 이슈에서 맞춘다.

- 화면은 계산 결과를 표시하고 거래·턴 진행 요청을 전달한다. 가격과 자산 계산을 화면에 중복 구현하지 않는다.
- 거래는 검증을 통과한 뒤 현금·보유량·거래 내역을 함께 반영한다. 실패하면 전체 상태를 유지한다.
- AI 호출은 생성 결과를 검증한 뒤 시장 엔진으로 전달한다. API 키는 클라이언트에 포함하지 않고 서버 측에서 관리한다.
- 공통 상태, 함수 입출력, 오류 처리 방식과 수정할 파일을 맞춘 뒤 영역별 개발을 시작한다.

| 개발 영역 | 담당 범위 | 병행 개발 방법 |
| --- | --- | --- |
| 시장·거래 | 상태, 이벤트 적용, 매매, 자산, 턴·이력, 배당 | 화면에서 호출할 함수와 결과 예시를 먼저 공유한다. |
| 화면·차트 | 종목·주문·자산·뉴스 화면과 차트 | 예제 게임 상태로 화면을 만들고 시장 함수에 연결한다. |
| AI·이벤트 | 생성 요청, 응답 검증, 실패 처리 | 기존 이벤트 형식으로 예제를 만들고 시장 엔진에 연결한다. |

개인별 담당자는 팀 논의로 정한다. 단계별 작업은 완료 조건이 있는 이슈를 먼저 만들고, PR에 연결해 리뷰한다.

## 첫 통합 확인 시나리오

수수료와 세금이 없고 양의 정수 단위로 거래하는 기본안을 기준으로 다음 흐름을 확인한다.

| 동작 | 기대 결과 |
| --- | --- |
| 새 게임 시작 | 현금 1,000,000원, 삼송전자 50,000원, 보유 0주 |
| 삼송전자 2주 매수 | 현금 900,000원, 보유 2주, 총자산 1,000,000원 |
| 2% 상승 뉴스로 한 턴 진행 | 주가 51,000원, 주식 평가액 102,000원, 총자산 1,002,000원, 전체 수익률 0.2% |
| 보유 2주 전량 매도 | 현금 1,002,000원, 보유 0주, 총자산 1,002,000원 |
| 다시 시작 | 현금 1,000,000원, 초기 시세, 보유·거래·뉴스·가격 이력과 턴이 초기 상태로 복원 |

수동 확인과 함께 잔액 부족, 보유량 부족, 0·음수·소수 수량, 잘못된 이벤트, 재시작을 자동 테스트로 확인한다.
