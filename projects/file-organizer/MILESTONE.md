# 📁 자동 파일 정리 프로그램 개발 마일스톤

> **프로젝트 목표:** 원본 파일을 변경하지 않고 별도의 결과 폴더에 **심링크(Symlink, 원본 파일을 가리키는 링크 파일)**를 생성하여 정리하는 CLI 프로그램을 먼저 완성합니다. 이후 LLM 기반 분류, 파일 내용 읽기, 실제 파일 이동, 그래픽 화면(GUI), 외부 AI 연동(MCP) 기능을 단계적으로 추가합니다.

---

## 1. 핵심 설계 원칙 및 합의 기준

> [!IMPORTANT]
> 제안된 마일스톤 계획서를 통해 확인된 합의 사항입니다.

1. **원본 보존 및 격리된 출력 폴더 사용**
   - **1단계(핵심 기능)**에서는 원본 파일을 이동, 수정, 삭제하지 않습니다. 원본 폴더(`source_root`)와 완전히 분리된 별도의 결과 폴더(`output_root`, 예: `Organized_View/`) 내부에만 심링크를 생성하여 정리된 폴더 구조를 만듭니다.
   - **2단계(확장 기능)**에서 사용자가 '실제 파일 이동' 옵션을 직접 선택한 경우에만 원본 파일을 이동시킵니다. 이 경우 프로그램 외부에서 파일을 옮기거나 이름을 바꾸면 추적이 불가능해 되돌리기(롤백)가 안 될 수 있음을 사전에 경고합니다.
2. **실행 환경 (Windows 우선 + Linux 테스트 지원)**
   - 로컬 NTFS 파일 시스템을 사용하는 **Windows를 최우선 실행 환경**으로 개발하며, Windows에서 심링크 생성에 필요한 권한이나 '개발자 모드' 활성화 여부를 먼저 확인합니다.
   - 개발과 테스트 편의를 위해 Linux 환경에서도 동일하게 동작하도록 운영체제별 차이를 분리하고 Python 표준 라이브러리 위주로 구현합니다.
3. **분류 기능 확장 순서 (규칙 기반 ➔ JSON LLM 분류 ➔ 선택적 결합)**
   - 초기에는 사용자가 정의한 **규칙(확장자, 파일명 등)**만으로 파일 탐색부터 되돌리기까지 전체 실행 흐름을 먼저 완성합니다.
   - 이후 LLM이 정해진 **JSON 형식**으로 정리 계획을 제안하는 기능을 추가하며, 규칙 기반과 LLM을 함께 사용하는 하이브리드 방식은 나중에 선택적으로 구현합니다.
4. **의미 정보를 유지하는 고유 번호(`file_id`) 매핑**
   - LLM에게 로컬 컴퓨터의 전체 절대 경로(예: `C:\Users\사용자명\...`)는 전달하지 않고, 각 파일에 고유 번호(`file_id`)를 부여하여 매핑합니다.
   - 동시에 LLM이 파일의 용도를 정확히 판단할 수 있도록 **파일 이름, 확장자, 원본 폴더 기준 상대 경로, 파일 크기, 수정 날짜** 정보는 함께 전달하여 이름과 경로에 포함된 의미(Semantic) 정보를 활용합니다.
5. **파일명 충돌 사전 해결 및 재승인**
   - 결과 폴더에 이미 동일한 이름의 파일이 있을 때 `보고서 (1).pdf`처럼 파일명을 변경하는 규칙은 **실행 전 미리보기 단계에서 미리 확정**해 사용자에게 보여줍니다.
   - 사용자가 승인한 직후부터 실제 실행 사이에 외부 요인으로 동일한 이름의 파일이 새로 생성되면, 프로그램이 임의로 이름을 다시 바꾸지 않고 **작업을 중단한 뒤 사용자에게 재검토 및 재승인**을 요구합니다.
6. **중단 시 복구 및 보수적 되돌리기(Rollback)**
   - 정리 작업 도중 프로그램이 강제 종료되더라도 실행 기록을 확인하여 중단된 지점부터 이어서 실행하거나 안전하게 원상복구할 수 있게 합니다.
   - 되돌리기를 실행할 때는 프로그램이 직접 생성한 심링크와 비어 있는 생성 폴더만 삭제하며, 외부에서 수정되거나 대체된 파일은 강제로 삭제하지 않고 충돌로 보고합니다.

## 2. 모듈 독립성을 위한 공통 데이터 규격 (예시)

팀원(Role A~D)의 역할이 중간에 변경되거나 각자 병렬로 개발하더라도 각 기능을 독립적으로 구현하고 연결할 수 있도록, 모든 모듈은 아래 3가지 표준 JSON 데이터 형식만을 주고받습니다.

```json
// 1. 탐색 결과 (파일 탐색기 -> 분류기)
// 폴더에서 찾은 파일의 기본 정보와 사용자가 정렬 대상으로 선택했는지 여부를 저장합니다.
{
  "file_id": "f_0001",
  "rel_path": "프로젝트A/2026_최종보고서.pdf",
  "name": "2026_최종보고서.pdf",
  "ext": ".pdf",
  "size_bytes": 1048576,
  "mtime": "2026-11-14T10:30:00Z",
  "selected": true
}

// 2. 정리 계획안 (분류기 -> 검증기 -> 검토 화면 -> 실행기)
// 어떤 파일을 어느 경로로 정리할지, 이름 충돌로 변경될 파일명은 무엇인지 사전에 확정한 데이터입니다.
{
  "plan_id": "p_0001",
  "file_id": "f_0001",
  "action": "symlink",
  "target_rel_path": "문서/PDF/2026_최종보고서 (1).pdf",
  "reason": "확장자(.pdf) 규칙 일치 및 기존 파일명 충돌 사전 변경",
  "approved": true
}

// 3. 작업 실행 기록 (실행기 -> 중단 복구 / 되돌리기)
// 실제로 심링크를 생성하거나 파일을 이동한 내역을 순서대로 저장하는 실행 로그입니다.
{
  "job_id": "job_20261115_01",
  "seq_no": 1,
  "file_id": "f_0001",
  "src_abs_path": "D:\\Downloads\\프로젝트A\\2026_최종보고서.pdf",
  "dst_abs_path": "D:\\Organized_View\\문서\\PDF\\2026_최종보고서 (1).pdf",
  "action": "symlink",
  "status": "COMMITTED",
  "timestamp": "2026-11-15T12:00:00Z"
}
```

## 3. Phase 1: 핵심 기능 구현 (CLI 기반 심링크 정리 MVP)

> **목표:** 터미널(CLI) 환경에서 안전하게 파일을 선택하고, 규칙과 LLM으로 정리 계획을 생성한 뒤, 심링크를 만들고 되돌릴 수 있는 핵심 프로그램을 완성합니다.

### M0. 안전장치 및 실행 환경 검증
- [ ] **Unit 0.1 운영체제별 심링크 권한 확인기**
  - **목적 및 기능:** Windows에서 심링크를 생성할 수 있는 권한(관리자 권한 또는 개발자 모드)이 활성화되어 있는지 실행 전에 점검하고, 권한이 없으면 설정 방법을 안내합니다. Linux 환경에서도 동일한 인터페이스로 작동하도록 구현합니다.
- [ ] **Unit 0.2 허용 경로 이탈 차단기 (보안 검증)**
  - **목적 및 기능:** 원본 폴더(`source_root`)와 결과 폴더(`output_root`)가 서로 겹치거나 한쪽이 다른 쪽의 하위 폴더가 되지 않도록 제한합니다. 또한 `../` 같은 상위 폴더 이동 경로가 입력되더라도 실제 파일 시스템 경로를 끝까지 확인하여 허용된 폴더 바깥으로 나가는 작업을 차단합니다.
- [ ] **Unit 0.3 원본 보호 전용 파일 처리 모듈**
  - **목적 및 기능:** 원본 파일을 삭제하거나 덮어쓰는 함수가 실수로라도 호출되지 않도록, 심링크 생성과 조회 등 허용된 파일 작업만 수행하는 전용 모듈을 작성합니다.

### M1. 파일 탐색, 선택 및 규칙 기반 정리 계획 생성
- [ ] **Unit 1.1 기본 폴더 탐색기 및 제외 목록(블랙리스트) 필터**
  - **목적 및 기능:** 지정된 원본 폴더 안의 파일 목록을 읽어오되, 숨김 파일(`.*`), 시스템 파일(`desktop.ini`, `.DS_Store`), `.git` 폴더처럼 정리하면 안 되는 항목은 탐색 단계에서 제외합니다.
- [ ] **Unit 1.2 CLI 정리 대상 파일 선택기**
  - **목적 및 기능:** 탐색된 파일 목록을 터미널 화면에 출력하고, 사용자가 실제로 정리할 파일만 체크박스로 선택할 수 있게 합니다. 선택하지 않은 파일은 이후 분류와 LLM 전송 대상에서 완전히 제외합니다.
- [ ] **Unit 1.3 규칙 기반(Rule-based) 분류기**
  - **목적 및 기능:** 파일 확장자(`.pdf`, `.jpg` 등), 파일 이름에 포함된 특정 단어, 수정된 연도·월 등의 사전 정의 규칙을 적용해 결과 폴더 내 이동할 경로를 결정합니다.
- [ ] **Unit 1.4 파일명 충돌 사전 해결기**
  - **목적 및 기능:** 심링크를 생성하기 전에 결과 폴더에 이미 동일한 이름의 파일이 있는지 미리 검사합니다. 이름이 겹치면 확장자를 유지한 채 `보고서 (1).pdf` 형태로 변경될 이름을 미리보기 계획서에 미리 확정해 저장합니다.

### M2. 계획 검토 후 심링크 적용, 중단 복구 및 되돌리기 (`내부 테스트 버전`)
- [ ] **Unit 2.1 정리 전후 비교 미리보기 및 수정·승인 화면**
  - **목적 및 기능:** `[원래 위치] -> [정리될 위치]`와 이름 변경 여부를 표 형태로 출력합니다. 사용자가 항목별로 승인하거나 제외할 수 있고, 목적지 폴더 경로를 직접 수정할 수도 있습니다(수정 시 경로 보안 검사와 이름 충돌 검사를 다시 수행합니다).
- [ ] **Unit 2.2 실행 직전 상태 재확인 및 심링크 생성기**
  - **목적 및 기능:** 사용자가 승인한 직후부터 실제 심링크를 생성하는 사이에 외부에서 새 파일이 생겨 이름 충돌이 발생하는지 다시 확인합니다. 새로운 충돌이 발견되면 임의로 이름을 변경하지 않고 실행을 멈춘 뒤 사용자에게 재승인을 요청합니다.
- [ ] **Unit 2.3 실행 기록 및 중단 시 복구 기능**
  - **목적 및 기능:** 심링크를 생성하기 직전에 '작업 예정(`PENDING`)' 상태를 기록하고, 생성 직후 '완료(`COMMITTED`)' 상태로 갱신하여 진행 상황을 저장합니다. 작업 도중 프로그램이 강제 종료되더라도 재실행 시 중단된 지점을 파악해 이어서 완료하거나 안전하게 원복하며, 같은 계획을 다시 실행해도 중복 작업이 발생하지 않게 합니다.
- [ ] **Unit 2.4 보수적 심링크 되돌리기(Rollback) 기능**
  - **목적 및 기능:** 실행 기록에 남아 있는 심링크와 이 작업 때문에 새로 생성된 **비어 있는 폴더**만 역순으로 삭제하여 정리 전 상태로 되돌립니다. 원본 파일이 외부에서 이동되어 연결이 끊어진 심링크는 정상적으로 삭제하되, 심링크 위치에 다른 일반 파일이 덮어써진 경우에는 삭제하지 않고 충돌로 보고합니다.

### M3. LLM 기반 분류 기능 추가 (`CLI 핵심 기능 완성`)
- [ ] **Unit 3.1 파일 정보 요약 및 LLM 요청 데이터 생성기**
  - **목적 및 기능:** 사용자가 선택한 파일들의 고유 번호(`file_id`), 파일명, 확장자, 원본 기준 상대 경로, 크기, 수정일과 현재 결과 폴더의 하위 구조를 정리해 LLM에 전달할 입력 데이터를 만듭니다. (개인정보가 포함될 수 있는 전체 절대 경로는 제외합니다.)
- [ ] **Unit 3.2 정해진 JSON 형식으로만 LLM 응답받기 및 검증기**
  - **목적 및 기능:** LLM이 자유로운 문장 대신 반드시 `[{"file_id", "target_rel_path", "reason"}]` 형태의 JSON 형식으로만 응답하도록 제한합니다. LLM이 존재하지 않는 파일 번호를 반환하거나 상위 폴더(`../`) 경로를 제안하는 등 잘못된 응답을 보내면 즉시 차단하며, API 오류가 발생하더라도 기존 규칙 기반 기능은 정상 작동하도록 격리합니다.
- [ ] **Unit 3.3 기존 검토·심링크 실행·되돌리기 흐름에 연결**
  - **목적 및 기능:** LLM이 생성한 정리 계획을 M1.4(파일명 충돌 사전 해결) 및 M2(미리보기 승인·심링크 생성·되돌리기) 과정에 그대로 연결하여 LLM 기반 CLI 정리 기능을 완성합니다.

## 4. Phase 2: 추가 확장 기능 (고도화 및 병렬 개발)

> **목표:** 핵심 기능이 완성된 후, 탐색 범위를 세밀하게 제어하고 파일 내용 읽기, 실제 파일 이동, 그래픽 화면(GUI), 외부 AI 연동(MCP) 기능을 추가합니다.

### M4. 폴더 탐색 깊이 설정 및 파일 내용 읽어서 분류하기
- [ ] **Unit 4.1 탐색 깊이(Depth) 제한 및 제외 폴더 설정**
  - **목적 및 기능:** 하위 폴더를 몇 단계 깊이까지 탐색할지(`--max-depth N`) 지정하고, 탐색에서 제외할 특정 폴더 목록(`.organizerignore` 파일 또는 명령어 옵션)을 사용자가 직접 설정하는 기능을 추가합니다.
- [ ] **Unit 4.2 파일 본문 내용 일부 추출기**
  - **목적 및 기능:** 사용자가 내용 읽기를 직접 허용한 `.txt`, `.md`, `.pdf`, `.docx` 문서에 한해 앞부분 핵심 텍스트만 정해진 글자 수(토큰) 제한 내에서 읽어옵니다. 암호가 걸려 있거나 읽을 수 없는 파일은 사유를 표시하고 건너뛰며, LLM에 전송될 내용 범위를 사용자에게 미리 보여줍니다.
- [ ] **Unit 4.3 (선택 사항) 규칙 기반 + LLM 하이브리드 분류 연결**
  - **목적 및 기능:** 사용자가 원할 경우, 1차로 규칙 기반 분류기가 명확한 파일을 먼저 분류하고 규칙에 해당하지 않은 나머지 파일만 모아서 LLM에 전달하는 결합 모드를 추가합니다.

### M5. 실제 파일 이동(Physical Move) 기능 및 경고 추가
- [ ] **Unit 5.1 실제 파일 이동 및 이름 변경 실행기**
  - **목적 및 기능:** 사용자가 별도 옵션(`--mode move`)으로 실제 이동을 직접 선택한 경우에만, 같은 드라이브(볼륨) 안에서 원본 파일을 실제로 옮기고 이름을 변경하는 기능을 추가합니다.
- [ ] **Unit 5.2 되돌리기 불가 경고 안내 및 역순 복구**
  - **목적 및 기능:** 실제 이동 모드를 선택할 때와 최종 승인 직전에 **"실제로 파일을 이동한 뒤 프로그램을 거치지 않고 외부에서 위치나 이름을 변경하면 추적이 불가능해 되돌리기(롤백)가 불가능할 수 있습니다"**라는 경고 문구를 표시하고 사용자 확인을 받습니다. 되돌리기 시에는 실행 기록과 일치하는 항목만 원래 위치로 복구하고, 외부에서 변경된 항목은 충돌로 보고합니다.

### M6. 그래픽 화면(GUI) 개발 *(M4, M5, M7과 병렬 개발 가능)*
- [ ] **Unit 6.1 Windows 우선 데스크톱/웹 화면(GUI) 구축**
  - **목적 및 기능:** 명령어 입력이 익숙하지 않은 사용자도 사용할 수 있도록 `PySide6`, `Flet`, `NiceGUI` 등을 이용해 시각적인 사용자 화면을 만듭니다. 폴더 선택, 파일 체크박스 선택, 정리 전후 트리 비교, 충돌 경고 확인, 실행 이력 조회 및 원클릭 되돌리기 버튼을 제공하며, 모든 실제 파일 처리는 이미 구현된 공통 핵심 엔진을 호출해 동작하게 합니다.

### M7. 외부 AI 도구 연동(MCP) *(M4~M6과 병렬 개발 가능)*
- [ ] **Unit 7.1 로컬 MCP(Model Context Protocol) 서버 연결**
  - **목적 및 기능:** Claude Desktop 등 외부 AI 클라이언트가 우리 프로그램의 기능을 도구(Tool)로 호출해 사용할 수 있도록 로컬 MCP 서버를 구현합니다. 파일 목록 조회와 정리 계획 생성 기능을 우선 제공하고, 실제 심링크 생성이나 되돌리기는 경로 검증과 사용자 승인 절차를 통과한 계획만 실행되도록 제한합니다.

### M8. 추후 고려 사항 및 미정 백로그 (Backlog)
- **해시 및 머클 트리(Merkle Tree) 기반 외부 변경 추적 (`미정 / TBD`)**
  - **내용:** 구체적인 개발 일정은 아직 정하지 않았으며, 추후 고도화가 필요할 때 파일의 고유 해시값(콘텐츠 해시)을 기록해 두었다가 외부에서 이름이 바뀌거나 이동된 원본 파일을 찾아 복구 후보로 제안하는 기능을 검토합니다.
- **보안 고도화 (`추후 고려 사항`)**
  - *문서 내 악성 지시문 방어(Indirect Prompt Injection):* M4에서 문서 내용을 읽을 때, 파일 본문 안에 포함된 악의적인 명령어가 LLM의 분류 결과를 조작하지 못하도록 본문을 단순 데이터로 격리 처리하는 방어 로직을 보강합니다.
  - *MCP 승인 우회 차단 고도화:* M7 연동 이후 외부 AI가 사용자 확인 없이 승인 값을 `true`로 전달해 실행하는 것을 차단하기 위해, 별도의 사용자 확인 토큰을 검증하는 절차를 추가합니다.

```text
file-organizer/
├── core/
│   ├── models.py            # 탐색 결과, 정리 계획, 실행 기록의 공통 데이터 규격
│   ├── sandbox.py           # [M0] OS 심링크 권한 확인 및 허용 경로 이탈 차단
│   ├── scanner.py           # [M1/M4] 폴더 탐색, 제외 목록(.organizerignore), 탐색 깊이 제어
│   ├── extractor.py         # [M4] 문서(TXT/MD/PDF/DOCX) 앞부분 내용 추출기
│   ├── classifiers/
│   │   ├── rule_engine.py   # [M1] 확장자·파일명 규칙 기반 분류기
│   │   ├── llm_engine.py    # [M3] LLM 요청 데이터 생성 및 JSON 기반 분류기
│   │   └── hybrid.py        # [M4] (선택) 규칙 기반 + LLM 하이브리드 연결기
│   ├── planner.py           # [M1] 파일명 충돌 사전 해결 및 정리 계획 관리
│   ├── executor.py          # [M2/M5] 실행 직전 재확인, 심링크 생성 및 실제 파일 이동기
│   └── journal.py           # [M2/M5] 실행 기록 저장, 중단 시 복구 및 되돌리기(롤백)
├── cli/                     # [M1~M3] 터미널 파일 선택기, 미리보기 승인 화면, CLI 명령어
├── gui/                     # [M6] Windows 우선 그래픽 화면(GUI)
├── mcp_server/              # [M7] 외부 AI 도구 연동을 위한 로컬 MCP 서버
└── tests/                   # [M0~M7] 경로 보안, 이름 충돌, 중단 복구, 중복 실행 방지 테스트
```
